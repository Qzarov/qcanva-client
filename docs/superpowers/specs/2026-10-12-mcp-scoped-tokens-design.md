# MCP: токены с правами, областью и сроком жизни

Дата: 12.10.2026.
Статус: основные решения приняты пользователем 12.10.2026 (раздел «Решения»). Ждёт ревью спеки.
Репозитории: `canvas-server-back` (основная работа), `canvas-server-front` (страница `/mcp`).
Связанное: роадмап — пункт «Токены MCP с правами и сроком жизни»; бэклог — «MCP → Фичи → Указание прав токена».

## Зачем

Сейчас MCP принимает обычный логин-токен: JWT на 7 дней, тот же, что у веб-сессии
(`McpAuthService` проверяет его и кладёт пользователя в контекст). Агент с таким токеном
может всё, что может владелец: удалять, расшаривать, менять доступы ко всем ресурсам. Токен
нельзя ограничить, отозвать отдельно от сессии или узнать, когда он использовался. Чтобы
дать агенту доступ, человек вынужден доставать токен своей сессии из браузера.

Нужны отдельные токены MCP, которые человек выпускает сам, с набором разрешённых действий,
областью ресурсов и сроком жизни.

## Решения

Приняты пользователем 12.10.2026:

1. **Область:** все ресурсы, выбранные папки (с подпапками и всем, что в них появится
   позже) или отдельные ресурсы. Папки и ресурсы можно сочетать.
2. **Действия:** пять отдельных галочек — чтение, правка, создание, удаление, управление
   доступом. Удаление и управление доступом по умолчанию выключены.
3. **Срок:** обязателен, 7 / 30 / 90 / 365 дней, по умолчанию 30. Бессрочных токенов нет.
4. **Логин-токен в MCP:** продолжает работать, но MCP предупреждает, что нужно перейти на
   токен MCP. Отключение — отдельным решением позже.

Главный принцип: токен только **сужает** права пользователя и никогда их не расширяет.
Действующее право = права пользователя на ресурс ∩ права токена. Сервисы ресурсов
по-прежнему проверяют роль пользователя; проверка токена добавляется до них.

## Токен

- Формат: `qcv_` + 32 случайных байта в base64url (43 символа). Префикс помогает узнать
  токен в конфигах и в сканерах утечек.
- Показывается **один раз** при выпуске. В базе хранится только SHA-256 от токена и
  первые 12 символов (`qcv_Ab12Cd34`) для отображения в списке.
- Поиск по хэшу (уникальный индекс). Сам токен нигде не логируется.
- Не больше 20 действующих токенов на пользователя.

### Сущность `McpToken` (бэк)

| поле | что |
|---|---|
| `id` | uuid |
| `userId` | владелец |
| `name` | имя от пользователя («Claude на ноуте»), до 80 символов |
| `tokenHash` | SHA-256 hex, уникальный |
| `tokenPrefix` | первые 12 символов |
| `actions` | `("read" \| "edit" \| "create" \| "delete" \| "share")[]`, не пустой, всегда содержит `read` |
| `scope` | `{ kind: "all" }` или `{ kind: "limited", folders: string[], resources: { type, id }[] }` |
| `expiresAt` | дата, обязательна, не дальше 365 дней от выпуска |
| `lastUsedAt` | обновляется не чаще раза в минуту |
| `createdAt`, `revokedAt` | отзыв мягкий: запись остаётся, токен перестаёт работать |

Таблица появляется через TypeORM `synchronize` (прод работает без миграций), поэтому перед
выкаткой бэка — бэкап базы.

## Авторизация MCP

`McpAuthService.getContext`:

1. `Bearer qcv_…` → найти по хэшу. Нет, отозван или истёк — ошибка `permission_denied`
   с понятным текстом («token expired on …», «token revoked»), без подсказки, существует ли
   чужой токен. Иначе контекст: пользователь-владелец (подгружается из `User`, с актуальной
   ролью) и `token: { id, actions, scope }`.
2. Иначе — как сейчас, JWT логина. Контекст помечается `legacyLogin: true`. Ответ
   `initialize` получает поле `instructions` с предупреждением: «Вы подключены логин-токеном.
   Выпустите токен MCP на https://qcanva.qzarov.pro/mcp — его можно ограничить и отозвать».
3. Токен MCP не годится для REST API приложения и для управления токенами: только для
   `/api/mcp`.

## Действия инструментов

Каждый `McpToolDefinition` получает обязательное поле `access` — какое действие нужно и
к какому ресурсу. Тест падает, если у зарегистрированного инструмента его нет, чтобы новый
инструмент нельзя было добавить без решения о правах.

| действие | инструменты |
|---|---|
| `read` | `*_list`, `*_search`, `*_get`, `resource_get`, `resource_search`, `*_history`, `*_history_get`, `html_doc_stream`, `text_doc_snapshot`, `text_doc_outline`, `resource_folder_list` |
| `edit` | `*_update`, `canvas_add_*`, `canvas_update_node`, `canvas_delete_node`, `canvas_delete_edge`, `canvas_batch`, `*_history_restore`, `text_doc_set_checked`, `text_doc_insert_blocks`, `text_doc_update_block`, `text_doc_delete_block`, `resource_folder_update`, `resource_folder_move`, `resource_folder_move_resource`, `resource_folder_clear_placement` |
| `create` | `canvas_create`, `html_doc_create`, `text_doc_create`, `resource_folder_create` |
| `delete` | `html_doc_delete`, `text_doc_delete`, `resource_folder_delete` |
| `share` | `*_share`, `*_revoke`, `*_permissions` |

Удаление узлов и блоков внутри документа — это правка документа (`edit`), а не `delete`.
Список доступов (`*_permissions`) отнесён к `share`: он показывает, у кого есть доступ, и
это не нужно агенту, которому не дали управлять доступом.

Проверка — централизованно в `McpToolsService.callTool`, до вызова обработчика:
нет действия в `token.actions` → `permission_denied` «this token cannot <action>».

## Область ресурсов

Ресурс в области токена, если область `all`, или ресурс указан в `resources`, или ресурс
лежит в одной из папок `folders` либо в их подпапках (по `parentId`). «Лежит в папке» —
по тому же правилу, по которому `resource_folder_list` показывает содержимое папки
(размещение ресурса, `UserResourcePlacement`). Ресурс, перенесённый в папку из области,
попадает в область; вынесенный из неё — выпадает.

Как инструменты учитывают область:

- **Один ресурс** (`*_get`, правки, удаление, шеринг, `resource_get`): `access.target(args)`
  называет тип и id/slug, slug разрешается в id тем же способом, что и в сервисе, затем
  проверка области. Вне области — `permission_denied` «outside this token's scope».
- **Списки и поиск** (`*_list`, `*_search`, `resource_search`, `resource_folder_list`):
  результат фильтруется по области после вызова сервиса. Папки вне области не видны, кроме
  предков папок из области — они показываются как путь, без содержимого.
- **Создание** при ограниченной области: нужен `folderId` папки из области, ресурс сразу
  кладётся в неё и поэтому остаётся доступен токену. Без папки — `invalid_request`
  «pass folderId of a folder this token covers». При области `all` — как сейчас.
- **Папки**: `resource_folder_create` внутри папки из области создаёт подпапку в области;
  перенос ресурса или папки разрешён, только если и источник, и цель в области.

Сами сервисы ресурсов не меняются: область и действия проверяет слой MCP, роль пользователя —
сервис, как сейчас.

## Управление токенами (REST)

Только для логин-сессии; токен MCP здесь не принимается.

- `GET /api/mcp-tokens` — свои токены: имя, префикс, действия, область (с названиями папок и
  ресурсов), срок, последнее использование, статус (действует / истёк / отозван).
- `POST /api/mcp-tokens` `{ name, actions, scope, expiresInDays }` → запись и **сам токен**,
  единственный раз. Проверки: `expiresInDays ∈ {7, 30, 90, 365}`, `read` всегда включено,
  папки и ресурсы области должны быть доступны пользователю хотя бы на чтение.
- `PATCH /api/mcp-tokens/:id` `{ name }` — переименовать. Права и область у выпущенного
  токена не меняются: нужен другой набор — выпустить новый.
- `DELETE /api/mcp-tokens/:id` — отозвать.

## Страница `/mcp` (фронт)

В меню аккаунта рядом с настройками. В стиле приложения, веб и мобилка.

- Список токенов: имя, `qcv_Ab12…`, чипы действий, область («Все ресурсы» / «3 папки, 2
  документа»), «истекает через 12 дней» / «истёк», «использовался 5 минут назад», кнопка
  «Отозвать» с подтверждением.
- Выпуск токена: имя; действия (чтение включено и заблокировано, правка и создание
  включены, удаление и доступ выключены); область: «Все ресурсы» или выбор папок и ресурсов
  (дерево папок + поиск по ресурсам); срок 7 / 30 / 90 / 365 дней, по умолчанию 30.
- После выпуска — токен один раз, кнопка «Скопировать» и готовый фрагмент конфига
  MCP-клиента с подставленным токеном. Закрыл окно — токен больше не показать.

## Тесты

Бэк:

- Авторизация: действующий токен, истёкший, отозванный, неизвестный, логин-JWT
  (работает и получает предупреждение в `initialize`); `lastUsedAt` обновляется не чаще
  раза в минуту.
- Каждый зарегистрированный инструмент имеет `access`; таблица действий совпадает с
  разделом «Действия инструментов».
- Действия: токен без `edit` не правит, без `delete` не удаляет, без `share` не видит
  доступы и не шарит.
- Область: ресурс в папке, в подпапке, указанный отдельно, вне области; slug внутри области;
  фильтрация списков и поиска; создание в папке из области и отказ без `folderId`; перенос
  в папку вне области запрещён.
- Не расширяет: токен с `edit` у пользователя с ролью `read` на ресурс — правка запрещена
  сервисом.
- REST: токен показывается один раз, в базе только хэш, токен MCP не управляет токенами,
  лимит 20, чужой токен нельзя отозвать.

Фронт: выпуск, показ один раз, список и отзыв; выбор области; мобильная раскладка.
