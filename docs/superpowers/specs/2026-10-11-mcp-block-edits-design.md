# MCP: точечные правки текстовых документов

Дата: 11.10.2026.
Статус: дизайн согласован пользователем; локальная реализация и самопроверка выполнены 11.10.2026. Мерж, выкатка и проверка на проде ещё не выполнены. Результаты: `../reports/2026-10-11-mcp-block-edits-verification.md`.
Репозитории: `canvas-server-back` (основная работа) и `canvas-server-front` (id блоков в редакторе).
Связанное: роадмап с отложенными пунктами — `docs/roadmap.html`,
https://qcanva.qzarov.pro/html/qcanva-roadmap.

## Зачем

Сейчас агент через MCP меняет текстовый документ только целиком: `text_doc_update`
с `html` удаляет всё содержимое и вставляет заново. Это:

- дорого: ради одной галочки агент гоняет весь документ (бэклог — около 28 КБ HTML);
- мешает людям: замена целиком идёт поверх того, что кто-то сейчас печатает;
- было небезопасно: до фикса `fix/mcp-text-doc-lossless` (11.10.2026) запись через
  HTML теряла id заголовков, упоминания и `checkedAt`. Фикс закрыл потери, но не
  первые два пункта.

Нужны точечные операции по образцу канвасов (`canvas_add_node`, `canvas_update_node`):
«отметь пункт», «допиши пункт в раздел», «поправь текст пункта».

## Согласованное поведение

Сценарии, выбранные пользователем: **отмечать пункты, добавлять пункты, править
текст блока**. Перестройка структуры (перенос, удаление разделов) — не в этой версии.

- Каждый блок документа адресуется стабильным `blockId`.
- Текст блоков на чтение и на запись — Markdown: что прочитал, то и правишь.
- Правка меняет только затронутый блок и доходит до открытых редакторов как правка
  соавтора, без перезагрузки.

## Инструменты MCP

Все принимают `id` документа (id или slug).

### `text_doc_outline` `{ id, section? }`

Чтение. Возвращает `{ revision, blocks }`. `blocks` — плоский список в порядке
документа:

| поле | что |
|---|---|
| `blockId` | стабильный id блока |
| `type` | `paragraph`, `heading`, `listItem`, `taskItem`, `blockquote`, `callout`, `codeBlock`, `image`, `table`, `horizontalRule` |
| `depth` | вложенность: 0 для блоков верхнего уровня, +1 на каждый уровень списка/контейнера |
| `markdown` | содержимое блока в Markdown (см. «Markdown»), без текста дочерних блоков |
| `level` | только у `heading` |
| `checked`, `checkedAt` | только у `taskItem` |
| `headingId` | только у `heading`, для ссылок `@[…](#headingId)` |

`section` — `blockId` заголовка: вернуть только его раздел, от заголовка до
следующего заголовка того же или более высокого уровня (не включая его).

Содержимое контейнеров (`listItem`, `taskItem`, `blockquote`, `callout`) отдаётся
их дочерними блоками со своими `blockId`; `markdown` самого контейнера — текст его
первого абзаца (для пунктов списков) или пустая строка (для цитаты и выноски).

### `text_doc_set_checked` `{ id, blockId, checked }`

Ставит или снимает отметку у `taskItem`. При `checked: true` пишет
`checkedAt` = текущее время (ISO 8601), при `false` удаляет `checkedAt`. Повторная
отметка уже отмеченного пункта ничего не меняет и `checkedAt` не перезаписывает.
Для блока другого типа — `invalid_target`.

### `text_doc_insert_blocks` `{ id, markdown, after? | appendToSection? | at? }`

Ровно один из трёх якорей:

- `after: blockId` — сразу после блока;
- `appendToSection: blockId` заголовка — в конец его раздела;
- `at: "start" | "end"` — начало или конец документа.

`markdown` может содержать несколько блоков. Возвращает `blockIds` созданных
блоков в порядке документа.

Правила вставки в структуру:

1. Якорь — пункт списка, вставляются пункты того же вида (обычные к обычным,
   задачи к задачам): пункты встают в тот же список, на уровень якоря, сразу после
   якоря и его подпунктов.
2. Якорь — пункт списка, вставляется другое (абзац, другой вид списка, заголовок):
   если якорь — последний пункт списка верхнего уровня, блоки встают после списка;
   иначе `invalid_target` с подсказкой «вставьте после последнего пункта или после
   блока вне списка».
3. `appendToSection`: якорь — последний блок раздела. Если раздел кончается списком
   того же вида, что и вставляемые пункты, они дописываются в этот список. Пустой
   раздел получает блоки сразу после заголовка.
4. Якорь — блок верхнего уровня не из списка: блоки встают после него.

### `text_doc_update_block` `{ id, blockId, markdown }`

Заменяет строчное содержимое одного блока. `markdown` — только строчный Markdown
(один абзац с форматированием); если в нём больше одного блока — `invalid_request`.

Сохраняются: `blockId`, тип, `level`, `collapsed`, `headingId`, `checked`,
`checkedAt`, вложенные пункты. У пунктов списков меняется текст первого абзаца.
Для `table`, `image`, `horizontalRule` — `invalid_target`. `codeBlock` принимает
текст как есть (без разбора Markdown), язык не меняется.

Передача неизменённого `markdown` из `outline` — no-op: исходный текст, пробелы,
форматирование и Yjs-структура сохраняются без повторного импорта и без новой
ревизии, если не требуется дописать отсутствующие id. Для `codeBlock` сравнивается
исходный текст кода без внешнего Markdown-ограждения.

### `text_doc_delete_block` `{ id, blockId }`

Удаляет один блок. Пункт списка — вместе с подпунктами; если список опустел, он
удаляется тоже. Заголовок удаляется только строкой, раздел под ним остаётся.
Если документ остаётся пустым, в нём остаётся один пустой абзац.

### Ответ и ошибки

Правки возвращают `{ revision, blockIds }` — затронутые или созданные блоки.

| код | когда |
|---|---|
| `block_not_found` | блока с таким `blockId` нет (например, его удалили) |
| `invalid_target` | операция не подходит к типу блока или позиции |
| `invalid_request` | неверные аргументы, несколько якорей, многоблочный Markdown в `update_block` |
| `capacity_exceeded` | вставка превысила бы лимит в 200 блоков верхнего уровня |
| `permission_denied` | нет права редактировать документ (для `outline` — читать) |

### Не в этой версии

Пакетные операции, перенос блоков, перестройка разделов, правка таблиц по
ячейкам — в роадмапе (`docs/roadmap.html`).

## Id блоков

**Схема.** Атрибут `blockId` добавляется в перечень узлов на обоих концах
(`src/text-documents/schema/schema-contract.ts` на бэке,
`src/documents/document-nodes.ts` на фронте) у узлов: `paragraph`, `heading`,
`listItem`, `taskItem`, `blockquote`, `callout`, `codeBlock`, `image`, `table`,
`horizontalRule`. Списки, строки и ячейки таблиц id не получают.

У заголовка `blockId` отдельный от `headingId`: ссылки на заголовки продолжают
держаться на `headingId`.

**Формат** — как у `headingId`: `${Date.now().toString(36)}-${случайные 8 символов base36}`.

**Фронт.** Расширение `BlockId` по образцу `HeadingId` (`src/text-documents/heading-id.ts`):

- `appendTransaction` после собственной правки пользователя выдаёт id блокам без
  него; загрузка документа, удалённые Yjs-правки и undo/redo сами по себе выдачу id
  не запускают;
- он же снимает дубли: при разделении блока (Enter посреди абзаца) и вставке копии
  атрибуты копируются, поэтому у второго и следующих блоков с тем же id id
  перевыдаётся, первый в порядке документа сохраняет свой;
- выдачи id в `onCreate` нет: иначе открытие старого документа создавало бы
  локальные Yjs-зависимости ещё до готовности отправки обновлений. Старый документ
  получает id при первой собственной правке либо при серверном `outline`.

**Бэк** выдаёт id своим новым блокам при вставке и дописывает недостающие у
существующих (документы, не открытые в новом редакторе):

- в начале любой правки через MCP — внутри той же Yjs-транзакции, что и сама правка;
- в `outline`, если в документе есть блоки без id: иначе агенту нечем адресовать
  блоки старого документа. Запись идёт тем же путём, что и правки (журнал,
  рассылка в редакторы), от имени `system`, а не вызывающего пользователя, и
  выполняется даже при праве только на чтение: видимое содержимое не меняется.
  Это единственный случай, когда чтение пишет; повторный `outline` по тому же
  документу ничего не пишет.

**HTML.** Рендер пишет `data-block-id` на элементе блока, импорт читает его обратно
(продолжение `fix/mcp-text-doc-lossless`). Импорт не берёт `blockId` из чужого
`id`. Повторяющиеся `data-block-id` во входном HTML: первый сохраняется, остальные
получают новые.

**Безопасность значения.** `blockId` — строка из `[A-Za-z0-9_-]`, до 64 символов;
иное значение из Yjs-обновления или HTML при рендере и чтении считается
отсутствующим (по образцу `clampCheckedAt`).

## Как правка доходит до документа

Внутренний метод сервиса `commitBlockEdit(documentId, user, edit)` по образцу
`commitContentReplacement`:

1. `withDocumentLock` — правки агента и людей не перемешиваются на сервере.
2. Текущее состояние Yjs → `Y.Doc`; одной транзакцией: дописать недостающие
   `blockId`, выполнить `edit` над `Y.XmlFragment`.
3. Обновление (`encodeStateAsUpdate(doc, before)`) пишется в журнал
   `text_document_update` с новой ревизией и `clientUpdateId` вида
   `server:block:<uuid>`.
4. Кэш состояния обновляется после коммита транзакции БД, затем `emitChange` —
   открытые редакторы применяют обновление как правку соавтора.

**Снимки истории.** Точечные правки полный снимок сразу не пишут: действует то же
правило периодичности, что и для правок из редактора (снимок раз в 50 ревизий).

**Права.** `outline` — `requireReadableDocument`, правки — `requireEditableDocument`.
Будущие токены с правами (отдельная спека) добавят проверку права токена здесь же:
`outline` — чтение, правки — редактирование.

**Одновременные правки.** Правки разных блоков сливаются средствами Yjs.
`update_block` заменяет текст блока целиком: ввод человека в этом же блоке в ту же
секунду может смешаться с новым текстом — принято для первой версии.

**Лимит.** `insert_blocks` проверяет лимит 200 блоков верхнего уровня
(`document-capacity`) до записи; при превышении документ не меняется.

## Markdown

### Вход

Markdown → HTML через `marked` (GFM, уже в зависимостях бэка) → существующий
HTML-импортёр (`projection/html-to-yjs.ts`) с его белым списком и санитизацией.

Доработки поверх `marked`:

- задачи `- [ ] текст` / `- [x] текст` → `<li data-checked="false|true">`;
- правило для `@[Подпись](doc:<id>)` → `<span data-mention-id="<id>">Подпись</span>`
  и `@[Подпись](#<headingId>)` → `<span data-heading-link-id="<headingId>">Подпись</span>`;
- сырой HTML экранируется и становится текстом, кроме `<u>…</u>`.

### Выход (`outline`)

| что | Markdown |
|---|---|
| жирный / курсив / код / зачёркнутый | `**…**` / `*…*` / `` `…` `` / `~~…~~` |
| подчёркнутый | `<u>…</u>` |
| ссылка | `[текст](url)` |
| упоминание / ссылка на заголовок | `@[Подпись](doc:<id>)` / `@[Подпись](#<headingId>)` |
| перевод строки внутри блока | `\` в конце строки |
| код | блок в тройных обратных кавычках с языком |
| картинка | `![alt](src)` |
| таблица | GFM-таблица, только чтение |

Специальные символы текста (`\ * _ ` [ ] ~ < >`, `#`, `-`, `+`, цифра с точкой в
начале строки) экранируются, чтобы `outline` → `update_block` того же текста не
менял документ.

## Тесты

Бэк:

- Markdown туда-обратно: для каждого типа блока и форматирования `outline` →
  `update_block` с тем же `markdown` не меняет документ (сравнение
  `prosemirrorJson`); экранирование, упоминания, задачи, сырой HTML как текст.
- Операции на Yjs: отметка ставит/снимает `checkedAt`; вставка после пункта — в тот
  же список; `appendToSection` — в последний список раздела и в пустой раздел;
  `update_block` сохраняет `blockId`, отметку, подпункты; удаление пункта с
  подпунктами и опустевшего списка.
- Ошибки: `block_not_found`, `invalid_target`, `invalid_request`,
  `capacity_exceeded`, `permission_denied`.
- Одновременная правка: Yjs-обновление «редактора» от той же базовой версии и
  серверная правка другого блока — обе сохраняются после слияния.
- Дописывание id: старый документ без `blockId` получает id один раз, все разные,
  повторный вызов ничего не пишет.
- `data-block-id` в HTML туда-обратно; дубли во входном HTML.
- Локально, без коммита: прогон по копии актуального бэклога, прочитанной через MCP
  (либо из бэкапа) —
  `outline`, затем `update_block` каждого блока его же `markdown`, документ не
  меняется.
- Мутационная проверка: по две поломки на ключевые места (структура и значения)
  должны валить тесты.

Фронт:

- `BlockId` выдаёт id новым блокам; Enter посреди абзаца — новый id у второй
  половины, первая сохраняет свой; вставка копии блока не даёт дубля.
