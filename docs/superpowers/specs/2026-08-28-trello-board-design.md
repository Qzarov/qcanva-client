# ТЗ: интерактивная Trello-like доска

## Цель

Добавить в QCanva новый интерактивный шаблон `trello-board`: совместно редактируемую канбан-доску. Полная доска открывается отдельным ресурсом из дашборда; на канвас она добавляется только как read-only превью со ссылкой на исходную доску.

## Границы первой версии

В первую версию входят:

- создание, редактирование, удаление и перемещение колонок;
- создание, редактирование, удаление и перемещение карточек внутри и между колонками;
- поля карточки: заголовок, описание, срок, метки, исполнитель, чек-лист;
- совместное редактирование в реальном времени;
- права владельца, редактора и читателя;
- добавление read-only превью доски на канвас.

В первую версию не входят вложения, комментарии, журнал активности, уведомления, фильтры, поиск, архивирование и автоматизации.

## Пользовательские сценарии

1. Пользователь выбирает «Канбан-доска» в меню создания на дашборде. Система создаёт доску с колонками «К выполнению», «В работе» и «Готово».
2. Владелец создаёт колонки, меняет их названия и порядок. При удалении колонки он выбирает: удалить её карточки либо перенести их в другую колонку.
3. Редактор создаёт карточку, задаёт её данные и перетаскивает карточку в пределах колонки или в другую колонку. Подключённые участники видят изменение без перезагрузки.
4. Владелец приглашает пользователей по email с ролью «редактор» или «читатель», меняет или отзывает доступ.
5. Пользователь добавляет доску на канвас. На канвасе показывается её компактное, не редактируемое превью. Нажатие на превью открывает исходную доску при наличии доступа.

## Данные

Интерактивный шаблон получает тип `trello-board`. Его данные хранятся как JSON-снимок, а ресурс имеет ревизию для согласования realtime-операций.

```ts
type BoardData = {
  version: 1;
  columns: BoardColumn[];
  cards: BoardCard[];
  labels: BoardLabel[];
};

type BoardColumn = {
  id: string;
  title: string;
  position: number;
};

type BoardCard = {
  id: string;
  columnId: string;
  position: number;
  title: string;
  description: string;
  dueAt: string | null;
  labelIds: string[];
  assigneeName: string | null;
  assigneeUserId: string | null;
  checklist: { id: string; title: string; completed: boolean; position: number }[];
};

type BoardLabel = {
  id: string;
  title: string;
  color: string;
};
```

Исполнитель всегда может быть произвольным именем. Если назначен участник доски, дополнительно хранится его `assigneeUserId`. При отзыве доступа связь с аккаунтом очищается, а последнее отображаемое имя сохраняется.

## Интерфейс

Редактор доски содержит:

- шапку с редактируемым названием, статусом синхронизации, списком участников и настройками доступа;
- горизонтально прокручиваемую область колонок;
- кнопку добавления колонки;
- кнопку добавления карточки в каждой колонке;
- drag-and-drop колонок и карточек;
- панель или диалог карточки для редактирования всех полей;
- на карточке: метки, исполнителя, дату срока и прогресс чек-листа;
- явное выделение просроченного срока.

Превью на канвасе показывает название, не более трёх первых колонок и ограниченное число карточек в каждой. Карточки в превью показывают заголовок, метки, срок и прогресс чек-листа. В ноде канваса сохраняется только идентификатор доски и параметры отображения, а не копия данных доски.

## Права доступа

Для интерактивных шаблонов добавляется общая модель прав, совместимая с остальными ресурсами:

- `owner`: управление содержимым, удаление и настройка доступа;
- `edit`: изменение колонок, карточек и порядка;
- `read`: только просмотр доски и превью.

Проверка роли обязательна в REST API, при подключении к realtime-комнате и при обработке каждой операции. Отозванный пользователь немедленно теряет доступ к дальнейшим событиям и снимку доски.

## API и realtime

REST API предоставляет создание, список, чтение, переименование и удаление досок, а также список, выдачу, изменение и отзыв прав. Запрос чтения возвращает актуальный снимок и ревизию.

Для realtime используется Socket.IO с отдельным каналом интерактивных шаблонов и комнатой `board:<boardId>`. При входе сервер аутентифицирует пользователя, проверяет роль и отправляет текущие `BoardData` и ревизию.

Клиент посылает минимальные операции с `clientOpId` и `baseRevision`:

- `column-add`, `column-update`, `column-remove`, `column-move`;
- `card-add`, `card-update`, `card-remove`, `card-move`;
- `label-add`, `label-update`, `label-remove`;
- `checklist-add`, `checklist-update`, `checklist-remove`, `checklist-move`.

Сервер атомарно применяет допустимую операцию, увеличивает ревизию, подтверждает её инициатору и рассылает участникам комнаты. При несовпадении ревизии клиент получает свежий снимок. Безопасные операции над отдельным полем или перемещение можно повторить после синхронизации; при конфликте редактируемого текста интерфейс показывает актуальные данные и сохраняет несохранённый локальный ввод для пользователя.

Транспорт и принципы подтверждений переиспользуют опыт realtime-движка канваса, но протокол, авторизация и операции доски остаются отдельными: канвасный канал не обобщается в рамках этой задачи.

## Ошибки и удаление

- Нет доступа или доска удалена: превью на канвасе показывает статус без содержимого и не раскрывает данные.
- Удаление колонки требует выбора обработки её карточек; операция не выполняется без выбора.
- Недоступный участник не может быть выбран в качестве нового исполнителя.
- Сетевая ошибка отображается в статусе синхронизации; локальная операция остаётся в очереди до подтверждения либо явного отклонения сервером.

## Критерии приёмки

1. Пользователь создаёт доску и сразу получает три стартовые колонки.
2. Владелец и редактор могут менять колонки и карточки; читатель не видит активных контролов редактирования и не может отправить операцию через API или сокет.
3. Два редактора видят создание, изменение и перетаскивание карточек в реальном времени.
4. Карточка корректно сохраняет все поля, в том числе текстового исполнителя и привязку к участнику.
5. При конфликте ревизий клиент восстанавливает актуальный снимок без повреждения данных доски.
6. Добавленное на канвас превью обновляется после изменений на доске, не позволяет редактировать карточки и открывает источник по клику.
7. Отзыв доступа исключает пользователя из realtime-комнаты и запрещает ему чтение доски и её превью.
8. Автотесты покрывают права, операции с ревизиями, перенос карточек, удаление колонок, сериализацию данных и состояние превью.
