# Первый шаг рефакторинга: CanvasLoaderApi — 12.10.2026

Ветка: `refactor/canvas-loader-api`, база: `origin/dev` / `e19e783`.
Ветка `fix/tabs-cleanup` и её коммит `09215f3` не включены.

## Согласованный объём

Типизированный публичный API существующего канваса; сохранение UI,
поведения и формата данных. Без разделения компонентов, переноса CSS,
смены realtime-протокола, мержа и деплоя. Работа выполнена без сабагентов.

## Сделано

- `src/canvas/loaderApi.ts`: явный список 85 публичных членов (методы и
  состояние), используемых CanvasView и MobileNodeToolbar. Сигнатуры
  получаются из реального экземпляра CanvasLoader через Pick/InstanceType;
  удаление члена из компонента ломает контракт при компиляции. Две копии
  сигнатур не поддерживаются. Исторические «79 методов» — другой показатель.
- Убраны `ref<any>` и `PropType<any>` у canvasRef обоих потребителей.
- Возвращаемые массивы getCanvasData получили типы реальных нод, связей и
  рисунков; формат снимка и JSON-клонирование сохранены.
- Описана фактическая возможность передать отсутствующее выделение в
  node lookup-методы. Операции используют id найденной ноды, без утверждения
  non-null для аргумента. Ничего не найдено — прежний no-op.
- Типизированы значения выравнивания и события выбора инструмента рисования.
  ActiveDrawingTool вынесен в существующий модуль drawing.ts; состав
  инструментов не менялся. Действия со связью вызываются без ранее
  передававшегося, но игнорировавшегося аргумента.
- Заглушки toolbar-тестов дополнены до полного типизированного контроллера;
  данные выбранного рисунка соответствуют Drawing. Проверки тестов сохранены.
