## Сделано

Грамматики bash, plaintext, css, javascript, json, python, sql, typescript,
xml вынесены в динамически импортируемый модуль. Импорт начинается при
первом блоке кода, в том числе загруженном с сервера или в read-only режиме.
Без кода запрос не выполняется. Одна регистрация и один pending import
разделяются между редакторами; порядок языков, aliases и auto-detection
сохранены. При отказе импорта текст остаётся доступным; загрузчик допускает
повторную попытку. Восстановление после сетевого отказа может потребовать
перезагрузки страницы из-за кэширования ошибок dynamic import браузером.

После регистрации обновляются только decorations. Сохранены исходные
плагины CodeBlockLowlight, включая paste из VS Code. Служебная транзакция
не меняет текст/атрибуты, selection, Yjs или undo-окно. Она намеренно НЕ
помечается addToHistory=false: y-prosemirror при такой метке вызывает
stopCapturing даже без изменения документа. Этот эффект воспроизведён
отдельным тестом и устранён до завершения работы.

Адаптация использует то, что CodeBlockLowlight@2.27.2 добавляет lowlight
state-plugin последним. При обновлении этой зависимости нужны повторные
регрессионные проверки lazy-refresh и сохранения VS Code paste.

## Замеры

Одна машина и Chrome 151, viewport 1440×1000, пять новых browser contexts
для каждого варианта до/после. Только синтетические документы; HTTP API
заменён fixture-ответами, внешняя сеть и WebSocket заблокированы. JS bytes
посчитаны по телам реально загруженных ответов; gzip — сумма gzipSync
каждого JS-ресурса, не измерение production transfer.

Без кода экономия 42443 bytes JS / 12142 gzip bytes. С кодом добавляется

с кодом немного вырос из-за загрузчика. Ускорение открытия не подтверждено
этими короткими локальными прогонами; замер с реальной сетью не проводился.

Сохранены файлы локального probe в /tmp/qcanva-code-highlighting-*.json
и скрипт /tmp/qcanva-code-highlighting-bench.mjs. Это временные артефакты,
не production-данные и не часть runtime приложения.

Независимого ревью, совместной серверной сессии и физического Android-теста
не было. Бэкенд, схема и документы куканвы не менялись. Пуш/мерж этой ветки,
деплой и тег не выполнены. I18n, адаптивность и разделение TextDocumentView
остаются отдельными следующими блоками.
