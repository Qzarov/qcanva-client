## Исправления, найденные самопроверкой

1. Удаление существующего блока могло возвращать успех без сохранения:
   сравнение Yjs state vector не учитывало изменения только delete set.
   Изменения теперь определяются по событию update транзакции. Регрессионный
   тест подтверждает новую ревизию, сохранение и применение обновления редактором.
2. Очистка текста блока страдала от той же причины. Отдельный тест подтверждает
   сохранение пустого текста без изменения blockId и соседнего блока.
3. Повторная запись неизменённого Markdown нормализовала пробелы и границы
   форматирования. Она теперь является no-op, включая сырой текст codeBlock.
   Регрессионный тест подтверждает сохранение состояния, ревизии и отсутствие
   ненужной рассылки.
4. Клиентская утилита удаления data-block-id из проверяемого HTML перенесена в
   `src/test-support/block-id.ts`; тестовый код не входит в расширение редактора.

Новые регрессионные тесты сначала упали на старом коде, затем прошли после исправлений.

## Известные падения вне этой задачи

`src/canvas/canvas-ruler.gateway.spec.ts`: мок chatService не реализует
`onMessageCreated`, вызываемый в `CanvasGateway.onModuleInit`. Те же семь тестов
падают до и после MCP-исправлений:

- first join respects disable received before the room settings cache exists
- first update cannot broadcast after disable without an initialized settings cache
- plugin disable clears guest/password room measurements without impersonating a user
- a delayed enabled lookup cannot resurrect a room disabled while the packet was pending
- a delayed settings lookup cannot roll back a newer owner notification
- a late unit notification cannot re-enable a plugin disabled in the meantime
- joining lookup finishing after leave cannot recreate room state or send a stale snapshot

Эти падения не исправлялись и не скрывались. Полный набор тестов бэкенда не зелёный;
решение об интеграции с известной исходной проблемой — за пользователем.

## Принятые решения и ограничения проверки

- Продолжена существующая feature-ветка; пользовательские изменения сохранены.
  Мутации изолированы во временной копии. Риск: параллельные правки могли бы
  повлиять на результаты; diff проверен перед коммитом.
- Для проверки взята текущая копия бэклога через read-only MCP вместо полной
  копии production-БД. Проверено именно её содержимое, не вся база; production
  документ не менялся. Временная копия не включена в Git.
- Сохранено решение клиентской реализации не выдавать id при загрузке/удалённых
  транзакциях. Иначе могла бы нарушиться отправка зависимых Yjs-изменений и undo.
  Старый документ получает id с первой собственной правкой либо через outline.
- Финальный просмотр выполнен автором без сабагентов по предпочтению пользователя.
  Это самопроверка, не независимое ревью.
- Нормализация пробелов HTML-импортёром при реально изменённом Markdown остаётся;
  повторная запись неизменённого текста теперь сохраняет исходный блок точно.
- Выпуск не объявляется завершённым до отдельной live-проверки этапа 11.

## Осталось для выпуска

Согласовать интеграцию с известными падениями линейки; влить и проверить обе
ветки; сделать production-бэкап; выкатить бэкенд с ОБЯЗАТЕЛЬНЫМ `npm ci`
(marked 16 → 15, совместимость CommonJS/Node 20), затем клиент. На отдельном
тестовом документе проверить все пять MCP-инструментов и получение изменений
открытым редактором без перезагрузки. Только затем обновить опубликованный MCP-док
и перевести соответствующий пункт обоих роадмапов в выполненные.
